## Flow particles: inverse-perspective fix + room-shared size/speed — DONE [confirmed] (2026-07-23)

The particle phase became a **delta-accumulated `flowClock`** (`updateFlow(timeDelta)`; the absolute-time `time * .00042` is gone) so live speed changes never teleport particles. ## LivePanel server launch fix #2 — shared capability-gated launch — RESOLVED [confirmed]

**Bug**: after fix #1, launching a LivePanel analysis still aborted, now with `historical-comparison-session-unavailable` logged as `SERVER: Error launching http server` / `SESSION_SERVER_MANAGER: Failed to start server` / `NEW_LAUNCHER_LIVEPANEL_ANALYSIS: Server could not be started`.

**Root cause**: `HttpServer`'s constructor (`src/servers/runtime/httpServer.ts`) eagerly constructed **all three** session-bound feature services — `HistoricalComparisonService`, `ProjectEvolutionService`, `DependencyGraphService` — for **every** session that carried an `analysisSessionId` (the `ServerLaunchOrchestrator` passes `{ sessionId }` for all modes). **Fix (common, future-proof launch)**: added `src/servers/runtime/analysisServerCapabilities.ts` — a single `resolveAnalysisServerCapabilities(analysisMode)` table declaring, per mode, which optional feature services the shared server attaches (`XR` → all three; `LivePanel` → dependency graph only; `VisualizeDOM` → none; unknown/undefined → none, so a brand-new mode still launches). `HttpServer` now looks up the session mode via `UnifiedSessionRegistry` and constructs each optional service only when its capability is granted. ## Baseline `?`-stripping corruption — RESOLVED [confirmed]

Discovered while validating Chat 2 (LivePanel Dependency Graph Summary): a `?`-stripping corruption traced via `git stash`/`git blame` to commit `87e80c75` ("chore: upload all changes and add Claude Code documentation"), predating Chat 2. Fixed across two sessions; `npm run compile`, `npm run typecheck`, `npm run lint`, and `npm test` (`test:basic`) are all green (0 errors, 305/305 unit tests) as of this snapshot.

- **Root cause pattern**: literal `?` characters were dropped throughout ~20 files by whatever produced commit `87e80c75` — from optional-chaining (`?.` → `.`), ternaries (`cond ? a : b` → `cond a : b`), regex escapes (`\?` inside `/.../` literals), non-capturing groups (`(?:` → `(:`), and even query-string literals (`'?'` → `''`). Some drops are silently-valid-but-wrong JS (a dropped ternary `?` reinterprets the remainder as a no-op labeled statement); others are hard `SyntaxError`s.
- **Fixed (first pass, prior session)**: `src/babia_templates/processing/templateProcessor.ts` — the `candidateFields` boolean-vs-array bug breaking all XR HTML generation.
- **Fixed (this session, full sweep)**: every remaining instance found via `node --check` + `grep` (double-space markers, `\w\.\(` optional-chain markers, `\w\.\[` bracket markers, `^\s*:` continuation lines) across:
  - TS sources: `dependencyGraphService.ts`, `directoryXRParser.ts`, `fileXRParser.ts`, `executePython.ts`, `directoryReAnalyzer.ts`, `reAnalysisManager.ts`, `gitRepositoryService.ts` (including a `split(/\r\n/)` → `split(/\r?\n/)` regex bug that broke Git timeline parsing on LF-only output), `historicalComparisonModels.ts`, `projectEvolutionService.ts`, `collaborationRoomServer.ts`, `httpServer.ts`.
  - Browser runtimes: `codexrCommonRuntime.js`, `codexrVisualStyleRuntime.js`, `analysisModeRuntime.js`, `analysisTableRuntime.js`, `dependencyGraphRuntime.js`, `historicalComparisonRuntime.js`, `projectEvolutionRuntime.js`, `xrChartMappingUiRuntime.js`, `codeXrBoatsRuntime.js` (~340 corruption sites total across these 9 files).
  - `templates/xr/file/xr-visualization.html` (`projectEvolutionRuntime.jsv=${nonce}` → `.js?v=${nonce}`).
  - Test files whose own regex assertions were corrupted the same way: `analysisModeMegatest.test.cjs`, `codeXrBoatsRuntime.test.cjs`, `dependencyGraph.test.cjs`, `historicalComparison.test.cjs`, `historicalComparisonRuntime.test.cjs` region, `projectEvolutionRuntime.test.cjs`, `xrAnalysisTableRuntime.test.cjs`, `xrDataSource.test.cjs`, `reanalysisArchitecture.test.cjs` (the last one updated legitimately — its assertions targeted the *pre-fix* signatures of `executePython.ts`/`reAnalysisManager.ts` options, not corruption).
  - A few adjacent, genuine null-safety gaps surfaced by the same test runs (not literal `?` drops, but revealed once the surrounding code started executing): `resolveControllerView`, `applyControllerView`, `setTableMode` in `analysisModeRuntime.js`; `table.components?.[...]` in `analysisTableRuntime.js`; `state.result?.revision`/`state.result?.bridgeUrl` in `projectEvolutionRuntime.js`.
- **Verification**: `node --check` per file, targeted `node --test` runs per affected suite, then full `npm test` (`typecheck` + `lint` + `compile-tests` + `test:unit`) and `npm run compile` (webpack) — all clean.
- **Residual risk**: this was found and fixed via static analysis + the existing automated test suite, not manual F5/browser verification of every XR mode (Historical Comparison, Project Evolution, Code City boats, dependency-graph XR). Recommend an F5 smoke pass across those modes before release, since some corrupted branches (e.g. deep in `code-xr-boats`, which is paused/out-of-scope for 1.2.0 but was fixed anyway per explicit user request) have no direct test coverage for their exact code paths.
