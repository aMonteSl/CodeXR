## What this version is for

**1.2.1 is a maintenance release. No new features.** The scope is: delete what is dead, shrink what is oversized, tighten what silently allows rot, and make the existing paths cheaper. Every change must be **behaviour-neutral for the user** unless the CHANGELOG says otherwise.

If a task turns out to need a behaviour change to be worth doing, stop and ask — it belongs in 1.3.0, not here.

## Cleanup backlog — ranked

Ranked by value-to-risk. Take **one item per session**, verify, update this doc and the CHANGELOG, commit. Do not bundle items.

### 1. ESLint config barely checks anything — the highest-leverage fix [confirmed]

`eslint.config.mjs` defines **five rules** (`naming-convention` for imports, `curly`, `eqeqeq`, `no-throw-literal`, `semi`) and **all of them are `warn`**. There is no `no-unused-vars`, no `no-explicit-any`, no `no-floating-promises`, and the TypeScript plugin is loaded but essentially unused.

**Consequence:** `npm run lint` passing today is close to meaningless, and `npm test` includes it as a gate. Dead variables, unused imports and unawaited promises pass silently — which is exactly the rot this version is supposed to remove.

**Do this first**, because every later item is easier once the linter can actually find things. Suggested order: enable `@typescript-eslint/no-unused-vars` and `no-unused-imports` → fix the fallout → then consider `no-floating-promises` (needs type-aware linting, `parserOptions.project`) → decide per-rule whether `warn` or `error`. Expect a large first fallout; land the config and the fixes together so the gate is never left red.

### 2. Dead file: `configurationManagerExample.ts` [confirmed]

`src/code_analysis/configuration/configurationManagerExample.ts` has **zero importers anywhere in `src/`** and contains 44 `console.log` calls. It is an example file that shipped into the source tree. Delete it.

### 3. `debugThemeProblem.ts` is a registered debug command [confirmed]

`src/code_analysis/configuration/debugThemeProblem.ts` (42 `console.log`) **is** imported — `src/commands/index.ts:15` registers `DebugThemeProblem`. So it is not dead, it is a debug tool exposed to end users in the command palette. Decide deliberately: remove the command, or gate it behind a development-only condition. **Do not just delete it** — the command ID is registered and `assertUniqueCommandIds` runs over that array.

### 4. 1,261 `console.log` vs a logger nobody uses [confirmed]

`src/core/logging/logger.ts` exports `ScopedLogger` and `CodeXRLogger`, but only **15 files** use it against **1,261** raw `console.log` calls. For a VS Code extension this is the wrong surface: `console.log` goes to a devtools console the user never opens, not to an output channel.

Worst offenders: `executePython.ts` (100), `multiServerLauncher.ts` (44), `configurationManagerExample.ts` (44, dead — see item 2), `debugThemeProblem.ts` (42), `serverControl.ts` (41), `visualizeDOMParser.ts` (35).

Migrate **area by area, not repo-wide in one commit**. Start with `executePython.ts` since it is both the worst offender and on the hot analysis path.

### 5. 34 MB of dead icons in the repo [confirmed measurement, self-assessed deadness]

`resources/languages_icons/no_color/` is 34 MB across 25 PNGs (~1.4 MB each). `V1.2.0_STATUS.md:132` states this set has been dead since `95f7c367` and it is already excluded from the VSIX `files` allowlist — so removing it does **not** change the published package, only the working tree and future clones. **Confirm the deadness independently** (grep for `no_color` across `src/`, `templates/`, `package.json`) before deleting.

Re-encoding them is a real VSIX size win. Carried over from `V1.2.0_STATUS.md:132`, where the debt was flagged but deliberately not taken.

### 8. `.git` is 1.03 GiB — **propose only, do not execute** [confirmed measurement]

The pack is dominated by binaries committed long ago: `code-xr-0.0.8.vsix` (55 MB and again at 38/36 MB), `code-xr-0.0.9.vsix` (37.6 MB ×3), `code-xr-0.0.6.vsix` (31.7 MB ×2), and `media/v1.1.0/gifts/*.gif` (43.5, 40.6, 37.5 MB).

Shrinking this requires **rewriting history** (`git filter-repo`), which changes every commit hash, forces a force-push to `origin`, and requires every clone to be re-made. That is destructive and outward-facing. **Never do it as part of a routine cleanup session.** If it is ever wanted, it is its own decision with its own explicit approval — and the current `.gitignore` should be checked first so no *new* build artifacts keep landing in history. **[open]**

**Found while building the net — real behaviour, pinned as it is, recorded for 1.3.0** (none of these is a cleanup):
1. **The dependency engine is not deterministic across processes.** `_normalize_reference` returns `list({...})` and the first candidate that resolves wins, so with the fixture corpus `#include "shared.h"` resolves to `shared.h` or to `shared.gd` depending on the interpreter's str hash seed. The goldens neutralize it with a sorting shim that must be deleted in the same change that makes the list ordered.
2. `JsonFieldAnalyzer.analyzeRecord` does `return` instead of `continue` on a null value: every field after the first null in a record is skipped for that record.
3. In brace languages `_infer_class_owner` makes a top-level function declared after a class a method of that class; with lizard the class counter reports the blank line above a class, so Python methods lose their owner; owner-by-name is a substring test (`rebase` belongs to `Base`).
4. `fileXRParser` copies `main.js` with a bare `copyFile` that is silently skipped when its source is missing, while `directoryXRParser` hard-fails on the same condition.
5. `resources/languages_icons/color/rust.svg` ships although no live code can reach it (there is no Rust entry in `languageMetadata`; the only source naming it is the dead `fileDisplayUtils.ts`).
6. `iconId` in `languageMetadata` and the `icon` field `getLanguageByExtension` adds have no reader anywhere; Fortran's extension order differs between the two live tables.
7. Visualization settings: storage and accessors disagree (for a file without colours the accessors return the globalState colours, `getSettings()` the defaults); the legacy migration has no "migrated" flag and every save still mirrors into the legacy key, so a deleted settings file is silently rebuilt. The audit labelled that migration "1.1.0 -> 1.2.0"; the three files are byte-identical from tag `v1.0.0` to HEAD, so it is older. It stays protected either way.
8. The `|auto` branch of the `clientCore.js` avatar regex is unobservable (a rejected id falls back to the default, which is also `auto`); the room server trims padded ids while the model and the browser reject them.
9. `analyze_classes` and the comment analyzer are silent for nine and six contract extensions respectively (`.pyw .pyi .rbw .mjs .cjs .hxx .zig .ttcn .ttcn3` / `.pyw .pyi .phtml .php3 .php4 .php5`).
10. A cache-only refresh of the dependency engine loses per-file read warnings; its "hash-based" cache writes `content_hash` but never compares it.
